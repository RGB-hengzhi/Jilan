# 2.2.2 内存优化说明

本版保留中文界面、即时名称检索、组合筛选、双栏多标签和文件整理，重点减少索引的重复路径与后台读取积压。索引共享父目录前缀；大小 / 日期候选在同一快照上计数，再分批检查；扫描利用新索引自身去重，目录与属性读取可在取消后停止继续排队。

## 实测口径

对同一批 2,220,920 条旧版 qfi 缓存，以相同的独立引擎测试程序分别运行 2.2.1 与 2.2.2，各三轮。测试只加载固定缓存并执行查询，没有遍历全盘。内存指标为程序自身读取的 macOS `phys_footprint`，查询预热后等待稳定；采用十进制 MB，1 MB = 1,000,000 字节。

| 指标 | 2.2.1 | 2.2.2 |
| --- | --- | --- |
| 三轮稳定内存范围 | 963.9–965.3 MB | 390.0–446.2 MB |
| 按中位数的降幅 | — | 59.5% |
| 按最保守对照的降幅 | — | 53.7% |

这组结果对应独立索引引擎，不能当作 GUI 全盘扫描、Quick Look、复制 / 移动或整理过程的内存峰值。实际占用还与索引量、目录层级、结果显示数量、属性检查、系统缓存与正在运行的任务有关。

同一测试中的六组查询，匹配数量保持一致。空查询、中文名称、组合条件和扩展名 OR 查询的中位耗时改善；两组极少命中或零命中的查询，从约 0.3–0.6 毫秒变为约 1.1–1.2 毫秒。因此，本说明不宣称所有查询都更快。

## 兼容与验证范围

- 沿用原应用身份、索引数据位置与旧 qfi 二进制格式。
- 源码保留原始 Cling 来源文件及 GPL-3.0-only 许可，未加入新的第三方运行依赖。
- 本包的 Sources、Tests、scripts 和 vendor 文件与 2.2.2（构建 9）的冻结构建清单逐字节一致；文件 SHA-256 见根目录 `SOURCE_SHA256SUMS`。
- 自动回归包含百万条索引、Unicode 字符边界、缓存校验与原子保存、分批候选、扫描边界、文件事件同步、实际临时文件操作及后台取消。

独立引擎数据和自动回归不代替另一台 Mac 的首次安装、Gatekeeper、授权和磁盘拔插实测。安装包使用 ad-hoc 签名，未经过 Apple 公证。
