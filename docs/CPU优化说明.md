# 2.2.3 后台更新 CPU 优化说明

疾览 · Jilan 2.2.3（构建 10，2026-10-04）减少文件事件更新的重复工作，保留即时名称搜索、组合筛选、双栏整理及旧索引兼容性。by 塔贰舅，免费使用，整体采用 GPL-3.0-only；索引核心继续保留 Cling 的来源与许可。

## 修改了什么

文件内容、大小和时间变化通过独立属性通知更新列表、筛选与预览；名称和路径没变时，不再重建名称树、重新执行名称查询或改写名称缓存。创建、删除、改名、类型变化、丢失事件恢复及必要校准仍会更新索引。

目录与未知路径的子树检查先检查共享父目录，减少对无关条目构造完整路径；同时保留目录边界、Unicode 规范等价和缺失祖先的后代清理。属性缓存覆盖旧查询与在途读取，预览匹配词法路径与后台解析的物理路径，未变化的结果不再因进度通知重复排序。

## 真实文件事件的受控对照

两版使用相同的 500,000 条虚拟缓存名称、一个真实测试文件及根目录节点，共 **500,002 条索引**。没有生成 50 万个物理文件。加载时取消启动校准以保留固定缓存，实际 FileWatcher/FSEvents 监听已启动。随后原地修改文件、创建 10 个文件、删除这 10 个文件，正常退出保存。

| 指标 | 2.2.2 基线 | 2.2.3 |
| --- | ---: | ---: |
| 系统实际投递的文件事件 | 22 | 22 |
| 内容修改前后名称 revision | 1 → 2 | 1 → 1 |
| 创建/删除后的条目数 | 500,012 → 500,002 | 500,012 → 500,002 |
| 退出保存后条目数 | 500,002 | 500,002 |
| 事件阶段进程 CPU 时间，含退出落盘 | 961.600 ms | 252.321 ms |
| 事件阶段墙钟时间，含事件合并等待与落盘 | 5.955 s | 5.436 s |
| 整个进程 CPU 时间，含缓存准备、加载及保存 | 3.556 s | 2.752 s |

事件阶段累计 CPU 时间减少约 **73.8%**；新版内容修改产生独立 metadata revision，创建和删除仍更新名称 revision。两次为自有目录的 CLI 工作负载，收到相同事件标志，计数与最终保存一致。

**73.8% 是这项受控工作负载的进程 CPU 时间降幅，不是整机 CPU、全盘静置占用、实际电耗或续航降幅。** 固定保留缓存也不表示全盘完整覆盖。本机测试设备为 Apple Silicon / macOS 27.0，MacBook 的实际功率与电池续航没有测量。

## 子树热点微基准

独立程序使用 500,000 个虚拟文件、50,001 个目录节点，共 **550,001 条索引**；只处理虚拟路径，不读取磁盘。下表为每项操作重复 3 次的**合计进程 CPU 时间**。

| 操作 | 2.2.2 | 2.2.3 |
| --- | ---: | ---: |
| 不存在的新路径子树检查 | 154.221 ms | 1.028 ms |
| 未知删除路径子树检查 | 154.758 ms | 0.776 ms |
| 新文件创建/删除循环 | 153.501 ms | 0.793 ms |

这组数据验证特定热点减少了重复路径处理，不能当作整个应用速度倍数。实际收益与目录分布、事件类型、扫描及系统负载有关。

## 回归与原生操作范围

最终源码完整自动回归通过，包括搜索、Unicode、缓存损坏、属性筛选、APFS/ExFAT 文件操作、扫描取消与超时保护、权限受限保留缓存和会话保存。本版新增内容事件、子树清理、跨查询缓存及符号链接预览范围测试。部分自动测试明确注入事件标志；上面的对照使用系统真实投递，两类证据分开理解。

原生界面在一个自建目录、3 条索引就绪后，中文关键词粘贴得到准确结果；文件原地从 8 KB 改成 12 KB，列表大小、预览信息与 Quick Look 内容自动更新。应用改名后旧查询为零、新查询立即命中；零结果按 Return 无动作，清空查询显示全部 3 项。中文粘贴不等同于输入法按键验收。

该自建目录的实际监听已确认可用，空查询、窗口可见时，30 秒内六次 5 秒 CPU 采样均为 0.0%。这是小目录的短时观察，不与旧版大索引占用直接计算降幅，也不代表大索引长期静置结果。

独立 QA 身份载入约 230 万条缓存的副本时，校准未完整结束，保留已有索引。采样显示监听准备卡在 `FSEventStreamCreate → watch_path → open`，属性读取卡在 `attributesOfItem → getxattr`。**这次运行未完成正常监听，其低 CPU 不作为性能证据。** 具体阻塞原因仍待核实，不能确定归因于路径映射、完全磁盘访问权限或读取超时。此项也没有证明全盘校准成功或所有位置已覆盖。

## 升级与使用

先按 `⌘Q` 完全退出旧版，再把新「疾览.app」放到旧版同一目录替换。原应用身份和 `~/Library/Application Support/QuickFind` 数据目录沿用，无需删除索引或设置，详见 [安装说明](安装说明.md)。启动校准、磁盘重连、丢失事件恢复或大量真实文件变化仍可能带来较高负载。

本次仍为 Apple Silicon / macOS 14+，使用 ad hoc 签名，未使用 Developer ID，也未经过 Apple 公证。其他 Mac 的首次启动、权限行为及低于本机测试系统的设备兼容性，仍需实际验证。若使用时持续异常，请反馈版本、索引状态和脱敏后的复现步骤，勿上传个人索引或私有路径清单。
